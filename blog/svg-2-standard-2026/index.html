SVG 2 Candidate Recommendation updated: what designers should test

W3C's October 2026 SVG 2 snapshot clarifies the vector format for implementers. It remains a Candidate Recommendation, and rendering still needs testing.

Source event: 6 October 2026 · Convertios published: 11 Nov 2026

What happened

The W3C announced on 6 October 2026 an updated Candidate Recommendation Snapshot of SVG 2. The SVG Working Group invites implementations and feedback. The specification itself labels this release a Candidate Recommendation Snapshot, not a final W3C Recommendation.

W3C describes corrections and clarifications intended to improve interoperability, especially in browsers. The announcement does not say that every SVG 2 feature now behaves identically in all browsers, editors, printers or image services. The stage of the standards process matters when planning a production design.

How SVG differs from raster images

SVG describes two-dimensional shapes, text and other graphical elements in XML. A browser can scale those shapes to different display sizes without the fixed pixel grid of a JPG or PNG. SVG may also include styling, mixed vector and raster content, or interactive behavior. A simple icon is usually easier to render consistently than a complex animated graphic with unusual effects.

For a printed QR code, a vector file can keep its edges crisp when resized. It does not make an unreadable code readable by itself: contrast, clear margin, destination data and the final printed size still matter. A bitmap export may be more predictable in software that has limited SVG support.

What it means for users

If you maintain a logo or diagram for several screen sizes, retain the source SVG and test its display in the browser and design tools your audience uses. For photos, a raster format often remains appropriate because the source is pixel-based. If a platform requests a particular file type, follow that requirement rather than assuming the latest SVG draft is supported.

The Convertios QR generator offers an SVG download for scalable QR artwork. Check the result at its actual print dimensions and scan it after export. If another service accepts only pixels, resize a raster image to its required dimensions and inspect the output. Our PNG versus SVG QR guide explains that choice in more detail.

Practical checklist

  • Confirm whether the destination accepts SVG, and which SVG features it supports.
  • Preview in target browsers and in the print or editing workflow, not only in the source editor.
  • Keep text, embedded images and external resources in mind when moving an SVG file.
  • For QR artwork, print a sample and scan it at the final size.

Limitations and what has not changed

A Candidate Recommendation is a stage for implementation experience and feedback, not a final Recommendation or a guarantee of uniform support. SVG's scalability does not repair a low-quality raster image embedded inside it, and it does not make a QR destination trustworthy. Continue checking the actual output and the needs of the receiving application.
