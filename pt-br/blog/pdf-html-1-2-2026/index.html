Algoritmo PDF para HTML 1.2 prioriza a estrutura, não a cópia visual da página

A PDF Association atualizou o método para gerar HTML a partir de PDFs bem marcados. O resultado depende da estrutura do documento e ainda precisa de revisão de acessibilidade.

  • Publicado11 de novembro de 2026
  • Data da fonte27 de setembro de 2026
  • CategoriaPDF e documentos
  • Leitura2 min de leitura

O que aconteceu

Em 27 de setembro de 2026, a PDF Association anunciou a versão 1.2 do seu algoritmo Deriving PDF to HTML. O documento orienta desenvolvedores que geram HTML estruturado a partir de PDFs bem marcados, principalmente material alinhado ao Well-Tagged PDF (WTPDF). É um método técnico, não a promessa de que qualquer PDF possa virar uma boa página web.

A associação compara a versão 1.2 com a 1.0 publicada. A versão 1.1 foi uma etapa interna e nunca chegou a ser publicada. Esse histórico ajuda a avaliar alegações sobre uma suposta versão 1.1 e evita tratar o novo número como prova de que algum conversor para consumidores mudou.

Por que o algoritmo importa

Uma captura de tela da página reproduz a aparência, mas não diz ao navegador o que é título, lista, link ou rótulo de formulário. A orientação revisada dá mais ênfase a mapear a estrutura do PDF para um HTML com significado, usando namespaces e informações de papel (role) de forma adequada, e a lidar com quebras e rótulos de página. Ela também trata de metadados como idioma e título, que ajudam o leitor a se orientar.

Pense em um relatório com sumário e formulário. Uma versão em HTML útil precisa de links que levem às seções certas, campos com rótulos compreensíveis e uma ordem de leitura que funcione em tela estreita. Não basta os pixels parecerem com o PDF. O WTPDF oferece uma estrutura de origem mais bem definida para apoiar essas decisões.

O que muda para quem usa

Se você publica documentos na internet, peça sempre que possível uma versão HTML acessível gerada no fluxo de criação original. Quando um fornecedor oferecer conversão de PDF para HTML, examine no resultado real os títulos, listas, links, campos de formulário e a ordem de leitura. Teste no celular, pelo teclado e com tecnologia assistiva, principalmente em formulários e instruções públicas.

A Convertios não oferece conversão de PDF para HTML. Para outra tarefa, você pode converter um PDF com texto para Word e trabalhar no conteúdo, ou exportar uma página do PDF como JPG para referência visual. Um JPG é uma imagem, não um documento HTML estruturado. As notas do PDF/UA-1 mostram por que a estrutura também importa dentro do PDF.

Checklist prático

  • Guarde o arquivo de origem editável e use a exportação web dele quando ela preservar a semântica.
  • Se gerar HTML a partir de PDF, confira níveis de título, listas, links, rótulos de formulário e navegação entre páginas.
  • Teste o resultado em telas estreitas, pelo teclado e com tecnologia assistiva.
  • Compare o HTML com o PDF para encontrar conteúdo omitido ou fora de ordem antes de publicar.

Limites e o que não mudou

A PDF Association avisa claramente que o HTML derivado não herda de forma automática as características de acessibilidade do PDF de origem. PDFs mal marcados ou feitos só de imagens oferecem pouca estrutura aproveitável. O algoritmo não corrige todos os erros de autoria, não faz OCR e não acrescenta uma ferramenta de PDF para HTML à Convertios. Trate qualquer resultado como um documento a revisar, e não como um certificado de acessibilidade.
