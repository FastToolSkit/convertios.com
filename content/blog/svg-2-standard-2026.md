<section><h2>What happened</h2><p>The <a href="https://www.w3.org/news/2026/updated-candidate-recommendation-scalable-vector-graphics-svg-2/">W3C announced on 6 October 2026</a> an updated Candidate Recommendation Snapshot of SVG 2. The SVG Working Group invites implementations and feedback. The <a href="https://www.w3.org/TR/SVG2/">specification itself</a> labels this release a Candidate Recommendation Snapshot, not a final W3C Recommendation.</p><p>W3C describes corrections and clarifications intended to improve interoperability, especially in browsers. The announcement does not say that every SVG 2 feature now behaves identically in all browsers, editors, printers or image services. The stage of the standards process matters when planning a production design.</p></section>
<section><h2>How SVG differs from raster images</h2><p>SVG describes two-dimensional shapes, text and other graphical elements in XML. A browser can scale those shapes to different display sizes without the fixed pixel grid of a JPG or PNG. SVG may also include styling, mixed vector and raster content, or interactive behavior. A simple icon is usually easier to render consistently than a complex animated graphic with unusual effects.</p><p>For a printed QR code, a vector file can keep its edges crisp when resized. It does not make an unreadable code readable by itself: contrast, clear margin, destination data and the final printed size still matter. A bitmap export may be more predictable in software that has limited SVG support.</p></section>
<section><h2>What it means for users</h2><p>If you maintain a logo or diagram for several screen sizes, retain the source SVG and test its display in the browser and design tools your audience uses. For photos, a raster format often remains appropriate because the source is pixel-based. If a platform requests a particular file type, follow that requirement rather than assuming the latest SVG draft is supported.</p><p>The <a href="/qr-generator/">Convertios QR generator offers an SVG download</a> for scalable QR artwork. Check the result at its actual print dimensions and scan it after export. If another service accepts only pixels, <a href="/image-resizer/">resize a raster image</a> to its required dimensions and inspect the output. Our <a href="/blog/qr-code-png-vs-svg/">PNG versus SVG QR guide</a> explains that choice in more detail.</p></section>
<section><h2>Practical checklist</h2><ul><li>Confirm whether the destination accepts SVG, and which SVG features it supports.</li><li>Preview in target browsers and in the print or editing workflow, not only in the source editor.</li><li>Keep text, embedded images and external resources in mind when moving an SVG file.</li><li>For QR artwork, print a sample and scan it at the final size.</li></ul></section>
<section><h2>Limitations and what has not changed</h2><p>A Candidate Recommendation is a stage for implementation experience and feedback, not a final Recommendation or a guarantee of uniform support. SVG's scalability does not repair a low-quality raster image embedded inside it, and it does not make a QR destination trustworthy. Continue checking the actual output and the needs of the receiving application.</p></section>
