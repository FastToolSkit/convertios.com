<section><h2>What happened</h2><p>On 9 September 2026, the <a href="https://pdfa.org/two-new-technical-notes-addressing-pdf-ua-1-implementations/">PDF Association published two PDF/UA-1 Technical Notes</a>. They clarify authoring and reading behavior for <code>ActualText</code> on a <code>Figure</code> structure element and for a <code>Reference</code> element that contains a link. The notes address interoperability questions, not a replacement for ISO 32000-1 or PDF/UA-1 requirements.</p><p>That distinction matters because a document can look correct on screen while its structure sends different information to a screen reader. The notes focus on how software exposes existing tags and annotations, rather than on redesigning a page's visible appearance.</p></section>
<section><h2>How the two cases work</h2><p>Technical Note 001 concerns non-text content whose purpose is to convey text. Under PDF/UA-1 it uses a Figure tag, yet announcing it simply as an image can obscure its meaning. The note recommends an appropriate surrounding structure, an <code>ActualText</code> value with the intended words, and inline placement. The accessibility interface should expose that value as text.</p><p>Technical Note 002 concerns references such as a table-of-contents entry or footnote reference. A <code>Reference</code> tag by itself is not necessarily clickable in PDF 1.7. If a link annotation is present, PDF/UA-1 also requires a <code>Link</code> tag around it. Both structures may reach assistive technology, but the same link should not be announced twice. PDF 2.0 permits a different structural arrangement, so reader behavior must account for the PDF version.</p></section>
<section><h2>What it means for users</h2><p>For someone navigating a long report by voice, repeated link announcements interrupt the flow; missing replacement text can change the meaning of an inline symbol. A visual spot check cannot reveal either problem. Ask the document author for an accessible source when a critical form, report or instruction sheet fails in your screen reader.</p><p>If you need editable material, <a href="/pdf-to-word/">convert a text-based PDF to Word</a> and review the extracted headings and links. To share selected pages as pictures, <a href="/pdf-to-jpg/">export PDF pages to JPG</a>, while recognizing that an image alone cannot preserve the PDF's tagged reading structure.</p></section>
<section><h2>Practical checklist</h2><ul><li>Check reading order and listen to representative pages with the intended assistive technology.</li><li>Inspect text-like graphics for meaningful replacement text, rather than relying on appearance.</li><li>Follow reference links and listen for duplicate or ambiguous announcements.</li><li>Fix the source document and regenerate the PDF when structural errors originate in authoring.</li></ul></section>
<section><h2>Limitations and what has not changed</h2><p>These notes do not perform OCR, tag an untagged PDF, or certify a converted file as accessible. A scan with no text layer remains a separate recognition problem; <a href="/blog/scanned-pdf-to-word/">our scanned-PDF guide</a> explains why ordinary conversion is insufficient. Even a formally tagged PDF needs real reader and assistive-technology testing for its intended audience.</p></section>

<section><h2>Qué ocurrió</h2><p>El 9 de septiembre de 2026, la <a href="https://pdfa.org/two-new-technical-notes-addressing-pdf-ua-1-implementations/">PDF Association publicó dos notas técnicas PDF/UA-1</a>. Aclaran el uso de <code>ActualText</code> en elementos <code>Figure</code> y de enlaces dentro de elementos <code>Reference</code>. Aquí importa la información estructural que recibe la tecnología de apoyo, no solo la apariencia del PDF.</p></section>
<section><h2>Cómo funcionan los dos casos</h2><p>La nota 001 trata contenido visual que en realidad comunica palabras. PDF/UA-1 exige una etiqueta Figure, pero anunciarlo únicamente como imagen perdería su sentido. La nota propone incluir la figura en una estructura apropiada, proporcionar las palabras en <code>ActualText</code> e indicar colocación en línea para que se expongan como texto.</p><p>La nota 002 distingue una referencia de una anotación de enlace. Una etiqueta Reference puede identificar una entrada del índice o una nota sin ser interactiva. Si existe un enlace en PDF 1.7, PDF/UA-1 requiere además una etiqueta Link. Ambas estructuras pueden llegar al lector asistido, pero el enlace no debería anunciarse dos veces. PDF 2.0 admite otra disposición, de modo que también cuenta la versión del archivo.</p></section>
<section><h2>Qué significa para los usuarios</h2><p>En un informe largo, un enlace repetido corta la navegación por voz; un símbolo sin texto alternativo puede cambiar el significado de una frase. Conviene escuchar páginas representativas con la tecnología de apoyo prevista y pedir al autor una fuente accesible si el documento importante falla.</p><p>Puedes <a href="/es/pdf-to-word/">convertir un PDF con texto a Word</a> para editarlo y revisar títulos y enlaces. También puedes <a href="/es/pdf-to-jpg/">exportar páginas PDF a JPG</a>, sabiendo que una imagen no conserva la estructura etiquetada del PDF.</p></section>
<section><h2>Lista práctica</h2><ul><li>Comprueba el orden de lectura con un lector asistido.</li><li>Revisa si los gráficos que representan palabras tienen texto significativo.</li><li>Activa referencias y escucha posibles anuncios duplicados.</li><li>Corrige el documento de origen y vuelve a generar el PDF cuando el error venga de la autoría.</li></ul></section>
<section><h2>Límites y lo que no cambia</h2><p>Las notas no hacen OCR, no etiquetan un PDF sin estructura ni certifican la accesibilidad de una conversión. Un escaneo sin capa de texto necesita reconocimiento aparte; consulta <a href="/es/blog/scanned-pdf-to-word/">la guía de PDF escaneados</a>. Incluso con etiquetas, hay que probar el archivo con las herramientas de lectura que usará la audiencia.</p></section>

<section><h2>O que aconteceu</h2><p>Em 9 de setembro de 2026, a <a href="https://pdfa.org/two-new-technical-notes-addressing-pdf-ua-1-implementations/">PDF Association publicou duas notas técnicas sobre o PDF/UA-1</a>. Elas esclarecem como softwares de criação e de leitura devem tratar o <code>ActualText</code> em um elemento de estrutura <code>Figure</code> e um elemento <code>Reference</code> que contém um link. As notas respondem a dúvidas de interoperabilidade; não substituem os requisitos da ISO 32000-1 nem do PDF/UA-1.</p><p>A diferença é importante porque um documento pode parecer perfeito na tela e, ao mesmo tempo, enviar informações diferentes para um leitor de tela. O foco está em como os programas expõem as tags e anotações que já existem, e não em mudar a aparência visível da página.</p></section>
<section><h2>Como funcionam os dois casos</h2><p>A Nota Técnica 001 trata de conteúdo não textual cuja função é transmitir texto, como um símbolo desenhado que representa uma palavra. No PDF/UA-1 ele usa a tag Figure, mas anunciá-lo apenas como "imagem" pode esconder o significado. A nota recomenda uma estrutura adequada ao redor, um valor de <code>ActualText</code> com as palavras pretendidas e posicionamento em linha com o texto. A interface de acessibilidade deve apresentar esse valor como texto.</p><p>A Nota Técnica 002 trata de referências, como uma entrada de sumário ou a chamada de uma nota de rodapé. Uma tag <code>Reference</code> sozinha não é necessariamente clicável no PDF 1.7. Quando existe uma anotação de link, o PDF/UA-1 também exige uma tag <code>Link</code> em volta dela. As duas estruturas podem chegar à tecnologia assistiva, mas o mesmo link não deve ser anunciado duas vezes. O PDF 2.0 permite outra organização estrutural, então o comportamento do leitor precisa considerar a versão do PDF.</p></section>
<section><h2>O que muda para quem usa</h2><p>Para quem navega por um relatório longo usando voz, anúncios repetidos de links quebram o ritmo da leitura, e a falta de texto substituto pode mudar o sentido de um símbolo. Uma conferência apenas visual não revela nenhum dos dois problemas. Se um formulário, relatório ou instrução importante falhar no seu leitor de tela, peça ao autor uma versão de origem acessível.</p><p>Se você precisa de material editável, <a href="/pt-br/pdf-to-word/">converta um PDF com texto para Word</a> e revise os títulos e links extraídos. Para compartilhar algumas páginas como imagem, <a href="/pt-br/pdf-to-jpg/">exporte páginas do PDF para JPG</a>, lembrando que uma imagem não preserva a estrutura de leitura marcada do PDF.</p></section>
<section><h2>Checklist prático</h2><ul><li>Confira a ordem de leitura e ouça páginas representativas com a tecnologia assistiva que o público usa.</li><li>Verifique se gráficos que parecem texto têm um texto substituto com sentido, em vez de confiar só na aparência.</li><li>Siga os links de referência e observe se há anúncios duplicados ou ambíguos.</li><li>Quando o erro de estrutura nasce na criação, corrija o documento de origem e gere o PDF de novo.</li></ul></section>
<section><h2>Limites e o que não mudou</h2><p>As notas não fazem OCR, não adicionam tags a um PDF sem estrutura e não certificam que um arquivo convertido é acessível. Um documento digitalizado sem camada de texto continua sendo um problema de reconhecimento separado; <a href="/pt-br/blog/scanned-pdf-to-word/">nosso guia sobre PDF digitalizado</a> explica por que uma conversão comum não basta. Mesmo um PDF formalmente marcado precisa ser testado com leitores e tecnologias assistivas reais do público a que se destina.</p></section>
