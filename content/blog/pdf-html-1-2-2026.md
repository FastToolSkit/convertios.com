<section><h2>What happened</h2><p>On 27 September 2026, the <a href="https://pdfa.org/deriving-pdf-to-html-version-1-2/">PDF Association announced version 1.2</a> of its Deriving PDF to HTML algorithm. The document is guidance for developers deriving structured HTML from well-tagged PDF, especially material aligned with Well-Tagged PDF (WTPDF). It is a technical method, not a promise that any arbitrary PDF can be turned into a good web page.</p><p>The association compares version 1.2 with the published 1.0 release. Version 1.1 was an internal intermediate and was never published. That history matters when evaluating claims about a supposed 1.1 release or treating the new number as evidence that a consumer converter has changed.</p></section>
<section><h2>How the algorithm matters</h2><p>A page screenshot reproduces appearance but does not tell a browser which text is a heading, list, link or form label. The revised guidance puts more emphasis on mapping PDF structure to meaningful HTML, using namespaces and role information appropriately, and handling page breaks and page labels. It also covers metadata such as language and title, which help readers navigate a document.</p><p>Consider a report with a table of contents and a form. A useful HTML version needs links that go to the right sections, fields with understandable labels, and an order that works on a narrow screen. It is not enough for the pixels to resemble the PDF. WTPDF gives implementers a more defined source structure on which to base those decisions.</p></section>
<section><h2>What it means for users</h2><p>If you publish documents online, ask for an accessible HTML source from the original authoring workflow when possible. When a vendor offers PDF-to-HTML conversion, examine headings, lists, links, form controls and reading order in the actual output. Check on mobile and with keyboard and assistive technology, especially for public forms or instructions.</p><p>Convertios does not offer PDF-to-HTML conversion. For a different task, you can <a href="/pdf-to-word/">convert a text-based PDF to Word</a> to work on its wording, or <a href="/pdf-to-jpg/">export a PDF page as JPG</a> for a visual reference. A JPG is a picture, not a structured HTML document. The related <a href="/blog/pdf-accessibility-2026/">PDF/UA-1 notes</a> show why structure also matters inside PDF.</p></section>
<section><h2>Practical checklist</h2><ul><li>Keep the original editable source and use its web export when it preserves semantics.</li><li>If deriving HTML from PDF, inspect heading levels, lists, links, form labels and page navigation.</li><li>Test the output on narrow screens and with keyboard and assistive technology.</li><li>Compare the HTML with the PDF for omitted or reordered content before publication.</li></ul></section>
<section><h2>Limitations and what has not changed</h2><p>The PDF Association explicitly cautions that derived HTML does not automatically inherit the accessibility characteristics of the source PDF. Poorly tagged or image-only PDFs offer less usable structure to derive. The algorithm does not repair every authoring mistake, perform OCR, or add a PDF-to-HTML tool to Convertios. Treat any output as a document to review, rather than as an accessibility certificate.</p></section>

La revisión detalla la correspondencia entre estructura PDF y HTML, roles, espacios de nombres, saltos de página, etiquetas de página y metadatos como idioma y título.</p><p>Imagina un informe con índice y formulario: una versión web útil debe permitir saltar a la sección correcta, explicar cada campo y mantener un orden de lectura adecuado en móvil. <section><h2>Qué significa para los usuarios</h2><p>Al publicar documentos, pide si es posible el HTML generado desde el archivo original de edición. Para otras tareas puedes <a href="/es/pdf-to-word/">convertir un PDF con texto a Word</a> para editarlo o <a href="/es/pdf-to-jpg/">exportar una página PDF a JPG</a> como referencia visual. JPG no es HTML estructurado. Las <a href="/es/blog/pdf-accessibility-2026/">notas PDF/UA-1 relacionadas</a> muestran por qué también importa la estructura interna del PDF.</p></section>
<section><h2>Lista práctica</h2><ul><li>Conserva el archivo editable y usa su exportación web cuando mantenga la semántica.</li><li>Revisa niveles de títulos, enlaces, campos y navegación entre páginas.</li><li>Prueba el HTML con pantalla estrecha, teclado y tecnología de apoyo.</li><li>Compara el contenido con el PDF para detectar omisiones y cambios de orden.</li></ul></section>
<section><h2>Límites y lo que no cambia</h2><p>La asociación advierte que el HTML derivado no hereda automáticamente la accesibilidad del PDF. Un documento sin etiquetas o compuesto por imágenes ofrece poca estructura utilizable. El algoritmo no realiza OCR, no repara todos los errores de origen ni añade a Convertios una herramienta PDF a HTML.</p></section>

O documento orienta desenvolvedores que geram HTML estruturado a partir de PDFs bem marcados, principalmente material alinhado ao Well-Tagged PDF (WTPDF). <section><h2>Por que o algoritmo importa</h2><p>Uma captura de tela da página reproduz a aparência, mas não diz ao navegador o que é título, lista, link ou rótulo de formulário. A orientação revisada dá mais ênfase a mapear a estrutura do PDF para um HTML com significado, usando namespaces e informações de papel (role) de forma adequada, e a lidar com quebras e rótulos de página. Ela também trata de metadados como idioma e título, que ajudam o leitor a se orientar.</p><p>Pense em um relatório com sumário e formulário. Uma versão em HTML útil precisa de links que levem às seções certas, campos com rótulos compreensíveis e uma ordem de leitura que funcione em tela estreita. Não basta os pixels parecerem com o PDF. O WTPDF oferece uma estrutura de origem mais bem definida para apoiar essas decisões.</p></section>
<section><h2>O que muda para quem usa</h2><p>Se você publica documentos na internet, peça sempre que possível uma versão HTML acessível gerada no fluxo de criação original. Quando um fornecedor oferecer conversão de PDF para HTML, examine no resultado real os títulos, listas, links, campos de formulário e a ordem de leitura. Teste no celular, pelo teclado e com tecnologia assistiva, principalmente em formulários e instruções públicas.</p><p>A Convertios não oferece conversão de PDF para HTML. Para outra tarefa, você pode <a href="/pt-br/pdf-to-word/">converter um PDF com texto para Word</a> e trabalhar no conteúdo, ou <a href="/pt-br/pdf-to-jpg/">exportar uma página do PDF como JPG</a> para referência visual. <section><h2>Checklist prático</h2><ul><li>Guarde o arquivo de origem editável e use a exportação web dele quando ela preservar a semântica.</li><li>Se gerar HTML a partir de PDF, confira níveis de título, listas, links, rótulos de formulário e navegação entre páginas.</li><li>Teste o resultado em telas estreitas, pelo teclado e com tecnologia assistiva.</li><li>Compare o HTML com o PDF para encontrar conteúdo omitido ou fora de ordem antes de publicar.</li></ul></section>
<section><h2>Limites e o que não mudou</h2><p>A PDF Association avisa claramente que o HTML derivado não herda de forma automática as características de acessibilidade do PDF de origem. PDFs mal marcados ou feitos só de imagens oferecem pouca estrutura aproveitável. O algoritmo não corrige todos os erros de autoria, não faz OCR e não acrescenta uma ferramenta de PDF para HTML à Convertios. Trate qualquer resultado como um documento a revisar, e não como um certificado de acessibilidade.</p></section>
